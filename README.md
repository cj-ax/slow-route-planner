# Slow Route Planner

A **personal** scenic route planner with a live GPS ride dashboard. Describe the ride you want in
plain language → an AI plans a low-stress, scenic route with editable, map-pinned waypoints that
**follow real roads** on a dark vector map → tap **Start Ride** for a full-screen **cockpit** that
tracks your live position against the route.

Built for one rider. No accounts, no auth, no production hardening — simple, readable, hackable.
Live at **<https://slow-route-planner.vercel.app>**.

> **Runs with zero API keys.** With nothing configured it serves realistic mock data (a Lake
> Minnetonka loop), a keyless dark map, and straight-line route segments, and shows a non-blocking
> "mock mode" banner. Add keys to switch on AI generation, road-following routes, real place search,
> and the vector map.

---

## Features

- **Prompt → plan.** Natural-language description → a `RoutePlan` with purpose-tagged waypoints
  (scenic, lake view, residential detour, route shaping, destination), avoid-roads, route notes, and
  manual-check reminders. Generated by Claude when a key is set, ordered to flow without backtracking.
- **Road-following map.** MapLibre + MapTiler dark vector tiles, color-coded waypoint markers, a
  legend, and a polyline that follows actual roads (via OpenRouteService). Click a waypoint to fly to
  it.
- **Editable.** Rename / re-query / reorder / lock / remove waypoints; search real endpoint options
  (coffee, beer, food, ice cream, view) via Google Places and set the destination.
- **Live cockpit (Ride Mode).** Full-screen dashboard: live location marker with heading, current
  speed, GPS quality, next waypoint + distance, off-route warning, follow mode, recenter, skip
  waypoint, screen wake lock, and a collapsible debug panel.
- **Save & reopen.** Routes persist to a local JSON file (and Vercel Blob in production), searchable
  on the Saved page, with rating + personal notes.
- **Open in Google Maps** as a turn-by-turn fallback.

---

## Opening the cockpit (Ride Mode)

Two ways:

1. **Right after planning** — generate a route and tap **▶ Start Ride — live cockpit**. This rides
   the route you're looking at immediately (held in the browser), so it works even before you save
   and even without a storage backend configured.
2. **From a saved route** — tap **Ride** on the Saved page (requires the route to have persisted; on
   Vercel that means a Blob store is connected — see Deploying).

Ride Mode needs **location permission** and a **secure context** (HTTPS, or `localhost`). For real
GPS on your phone, open the deployed URL there.

## Quick start

```bash
npm install
cp .env.example .env     # optional — runs in mock mode with no keys
npm run dev
```

- Client: <http://localhost:5173>
- API health: <http://localhost:3001/api/health>

Type a ride description (or use the prefilled example) → **Generate route** → edit waypoints / pick an
endpoint → **▶ Start Ride** for the cockpit, or **Save route** to keep it.

## Project structure

```
shared/   @srp/shared — domain types + pure utils (geo, format, googleMaps, waypoints); builds to dist/
server/   @srp/server — Express API: LLM, routing/geocoding, places, storage adapters
client/   @srp/client — React + Vite app (MapLibre map, Ride Mode cockpit, pages, hooks)
api/      Vercel serverless entry — re-exports the Express app as the function handler
```

npm **workspaces** monorepo: one `npm install` installs everything; `npm run dev` builds `@srp/shared`
then runs the server (`:3001`) + client (`:5173`) together.

## Environment variables

See [`.env.example`](.env.example) for the annotated list. All secrets are **server-side only**; the
sole client-exposed value is the map style URL.

| Variable | Side | Purpose |
| --- | --- | --- |
| `LLM_API_KEY` | server | Anthropic key for AI route generation. Blank → mock plans. |
| `LLM_MODEL` | server | Claude model. Recommended `claude-sonnet-4-6` (fast). Falls back to `claude-opus-4-8` if unset. |
| `ORS_API_KEY` | server | OpenRouteService — road-following geometry **and** waypoint geocoding. Blank → straight lines + un-pinned AI waypoints. |
| `GOOGLE_PLACES_API_KEY` | server | Google Places Text Search for endpoint options. Blank → mock places. |
| `USE_MOCKS` | server | `true` forces mock LLM/Places. Routing/geocoding ignore this (depend only on `ORS_API_KEY`). |
| `BLOB_READ_WRITE_TOKEN` | server | Auto-injected by Vercel Blob; switches storage from local JSON file to Blob. |
| `VITE_MAP_STYLE_URL` | client | MapTiler dark vector style. Blank → keyless CARTO raster fallback. Baked in at build time. |
| `VITE_API_BASE_URL` | client | API origin. **Leave blank** — dev proxies `/api` to `:3001`, Vercel serves it same-origin. |

### How the pieces work

- **LLM** ([`server/src/llm/client.ts`](server/src/llm/client.ts)) — calls the Anthropic Messages API
  via `@anthropic-ai/sdk` with prompt caching on the planner system prompt. Thinking is disabled for
  speed (well under Vercel's function timeout). LLM waypoints have no coordinates, so they're
  **geocoded** via ORS and then **reordered** (nearest-neighbour) so the road line flows. Any failure
  falls back to a mock plan so the app never breaks.
- **Routing + geocoding** ([`server/src/routing/`](server/src/routing)) — ORS `driving-car` geometry
  draws roads instead of straight lines (which otherwise cut across lakes); geocoding (same key) is
  constrained to a circle around the start so queries resolve in-area. The road geometry also powers
  Ride Mode's off-route detection.
- **Map** — set `VITE_MAP_STYLE_URL` to a free [MapTiler](https://www.maptiler.com/) dark style, e.g.
  `https://api.maptiler.com/maps/streets-v2-dark/style.json?key=YOUR_KEY` (restrict it by domain).
- **Places** ([`server/src/places/client.ts`](server/src/places/client.ts)) — Google Places Text
  Search; needs a billing-enabled key.

## Deploying to Vercel

The repo deploys as a static Vite client + one serverless Express function.

1. **Import the repo** (<https://github.com/cj-ax/slow-route-planner>) in Vercel.
   - **Root Directory:** the repo root (do *not* drill into `server/`).
   - **Framework Preset:** Other. The rest comes from [`vercel.json`](vercel.json): build →
     `client/dist`, `/api/*` → the Express function (`maxDuration` 60s), everything else → the SPA.
2. **Environment variables** (Settings → Environments → Production) — paste as a `.env` block:
   ```
   LLM_API_KEY=...
   LLM_MODEL=claude-sonnet-4-6
   ORS_API_KEY=...
   GOOGLE_PLACES_API_KEY=...
   VITE_MAP_STYLE_URL=https://api.maptiler.com/maps/streets-v2-dark/style.json?key=...
   USE_MOCKS=false
   ```
   Leave `VITE_API_BASE_URL` unset. **Redeploy after changing env vars** — `VITE_MAP_STYLE_URL` is
   baked into the client at build time.
3. **For saved routes to persist + sync across devices:** Storage → **Create → Blob** → connect it.
   Vercel injects `BLOB_READ_WRITE_TOKEN` and the server switches to Blob storage. Without it, the
   serverless filesystem is ephemeral, so saves don't stick — but **Start Ride still works** (it
   rides the in-browser plan). Redeploy after connecting.
4. Open the deployed URL on your phone, allow location, and ride.

> Verify with `https://YOUR-APP.vercel.app/api/health` — you want `mockMode:false` with the keys
> `true` (and `blobConfigured:true` once Blob is connected).

## Not included (by design)

Auth / accounts / admin, payments, production security hardening, turn-by-turn navigation, voice or
lane guidance, traffic rerouting, offline / background GPS, CarPlay / Android Auto. Routing uses the
`driving-car` profile for all ride types.

**Speed limits are a preference, not a guarantee.** Plans include a manual-check reminder to verify
speed limits before riding, and Google Maps may reroute onto faster roads — follow the planned
waypoints.
